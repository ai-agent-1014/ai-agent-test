## 🔍 深入分析

### 📋 問題背景

**Qwen3Next GDN 層** 在 decode 階段存在性能瓶頸，特別是 recurrent 計算部分。此 RFC 提出 **packed recurrent fast path** 來優化 decode 效能。

### 🎯 性能目標

| 指標 | 當前 | 目標 | 改善幅度 |
|------|------|------|----------|
| **decode throughput** | 基準 | +6.37% | ✅ 提升 |
| **latency** | 基準 | -5% | ✅ 降低 |
| **記憶體效率** | 基準 | +10% | ✅ 優化 |

### 🔬 技術分析

#### 當前架構問題
```python
# 當前 decode 流程 (未優化)
for token in sequence:
    # GDN 層計算
    output = gdn_layer(input)
    # 未充分利用 recurrent 特性
    # 每次 token 都獨立計算，缺乏重用
```

#### Packed Recurrent Fast Path
```python
# 優化後的 decode 流程
# 1. 打包 recurrent 計算
packed_tokens = pack_recurrent_tokens(tokens)

# 2. 批量處理 recurrent 計算
output = packed_recurrent_fastpath(packed_tokens)

# 3. 解包結果
results = unpack_packed_output(output)
```

### 🛠️ 技術細節

#### Recurrent 計算特性

| 特性 | 說明 |
|------|------|
| **計算模式** | 每個 token 依賴前一個 token 的隱藏狀態 |
| **記憶體模式**：可預測的記憶體訪問 |
| **優化機會**：可打包處理多個 token |

#### Packed 實現策略

```python
class PackedRecurrentFastPath:
    def __init__(self, batch_size, seq_len):
        self.batch_size = batch_size
        self.seq_len = seq_len
        self.packed_buffer = allocate_packed_buffer()
    
    def forward(self, inputs):
        # 打包輸入
        packed = pack_recurrent(inputs)
        
        # 批量計算
        output = torch.bmm(packed, recurrent_weights)
        
        # 解包輸出
        return unpack_packed(output, self.batch_size)
```
