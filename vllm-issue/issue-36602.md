# [RFC]: Make kernel/op and component tests device-agnostic for OOT plugins

- **Issue**: #36602
- **Author**: @romitjain
- **Created**: 2026-03-09T17:55:35Z
- **Labels**: `RFC`, `enhancement`

---

## 🔍 深入分析

### 📋 問題背景

vLLM 的 kernel 和 component 測試目前對特定設備（如 NVIDIA GPU）有強依賴，這限制了：
- **OOT (Out-of-Tree) 外掛開發**：第三方設備支援者需要修改核心測試
- **跨設備測試**：無法在 XPU、TPU 等其他加速器上驗證功能
- **CI/CD 穩定性**：測試失敗可能源於設備特定問題而非程式碼問題

### 🎯 RFC 目標

1. **抽象化設備依賴**：建立測試 abstraction layer，讓 kernel tests 自動適配不同設備
2. **標準化測試介面**：定義統一的測試 contract，確保 OOT 外掛可插拔驗證
3. **持續整合優化**：讓 CI 能同時測試多個設備類型

### 🛠️ 技術挑戰

| 挑戰點 | 說明 | 建議解法 |
|--------|------|----------|
| **設備抽象層** | 不同設備的 kernel 實現差異大 | 建立統一測試介面 + 設備特定實作 |
| **測試數據** | 某些測試需要特定設備特性 | 使用模擬數據 + 設備能力探測 |
| **CI/CD 複雜度** | 多設備測試增加 CI 時間 | 分階段測試 + 設備條件執行 |

### 💡 預期效益

- ✅ **降低 OOT 外掛門檻**：第三方開發者無需修改核心測試
- ✅ **提升測試覆蓋率**：多設備驗證確保跨平台穩定性
- ✅ **加速問題排查**：明確區分程式碼問題 vs 設備問題
