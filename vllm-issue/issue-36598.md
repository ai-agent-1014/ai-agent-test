# [Bug]: Triton autotuner OOM on Qwen3.5/Qwen3-Next GDN layers (non-SM90 GPUs)

- **Issue**: #36598
- **Author**: @AuYang261
- **Created**: 2026-03-08T17:29:43Z
- **Labels**: `bug`, `qwen`, `v1`

---

## 🔍 深入分析

### 📋 問題背景

**Qwen3.5 / Qwen3-Next** 模型使用的 **GDN (Grouped Document Network) 層** 在 vLLM V1 架構下的 **Triton autotuner** 存在記憶體管理問題，特別影響非 SM90 GPU。

### 🎯 問題詳情

#### 受影響設備
```
✅ 正常：H100 (SM90)
❌ 問題：RTX 4090 (SM89), RTX 3090 (SM86), L40S (SM89)
```

#### 問題表現
```bash
# 典型錯誤訊息
RuntimeError: Triton autotuner OOM
  at vllm/model_executor/layers/gdn_layer.py:XXX
  Failed to allocate XXX MB for autotuning
```

### 🔬 技術分析

#### GDN 層特性

| 特性 | 說明 |
|------|------|
| **功能** | 群組化注意力機制，提升長序列處理效率 |
| **計算密集** | 需要大量矩陣運算 |
| **記憶體需求** | autotuner 需要預先分配 buffer 進行性能測試 |

#### 記憶體分配邏輯問題
```python
# 問題：Triton autotuner 固定分配大 buffer
# 不考慮設備實際可用記憶體
autotune_buffer = allocate_fixed_size(size=MAX)
# 非 SM90 GPU 可能因記憶體限制而 OOM
```

#### 設備差異原因

| GPU 架構 | SM90 | SM89 | SM86 |
|----------|------|------|------|
| **設備類型** | H100 | RTX 4090/3090 | RTX 3090 |
| **記憶體管理** | 高效 | 較保守 | 較保守 |
| **Triton 支援** | 最佳 | 需調整 | 需調整 |

### 🛠️ 預期解決方案

1. **動態記憶體探測**：profiling 前檢測設備記憶體狀況
2. **漸進式 autotuning**：從小 buffer 開始，逐步增大
3. **設備特定配置**：為不同 GPU 架構設定不同的 autotune 參數

### 📈 影響評估

| 影響層面 | 嚴重度 | 說明 |
|----------|--------|------|
| **使用者體驗** | 🔴 高 | 模型無法啟動 |
| **設備支援** | 🟡 中 | 消費級 GPU 無法使用 |
| **性能** | 🟢 低 | 僅限 profiling 階段 |
