## 🔍 深入分析

### 📋 問題背景

此 issue 是 **#36598** (Triton autotuner OOM) 的修復方案，針對 **Qwen3.5 / Qwen3-Next 的 GDN (Grouped Document Network) 層** 在 V1 profiling 階段的記憶體問題。

### 🎯 核心問題

| 項目 | 說明 |
|------|------|
| **設備** | 非 SM90 GPU (RTX 4090, RTX 3090 等消費級顯卡) |
| **場景** | V1 推理的 profiling 階段 |
| **現象** | Triton autotuner 嘗試分配過大顯存 → OOM |
| **影響** | 模型無法啟動或首次 infer 失敗 |

### 🛠️ 修復機制

#### 問題根源
```python
# 問題：GDN 層 profiling 時直接嘗試大記憶體分配
# 導致非 SM90 GPU OOM
triton.autotune(large_memory_buffer)  # ❌ OOM
```

#### 解決方案
```python
# 修復：預先 warm up autotuner，避免突發性記憶體分配
def warmup_triton_autotuner_for_gdn():
    # 1. 使用較小 buffer 進行初步調校
    small_buffer = allocate_safe_buffer()
    triton.autotune(small_buffer)
    
    # 2. 逐步增大 buffer 直到穩定
    for size in progressive_sizes:
        if is_safe_to_allocate(size):
            triton.autotune(allocate(size))
    
    # 3. 完成後記錄最佳配置
    save_autotune_config()
```

### 📊 性能影響

| 指標 | 修復前 | 修復後 | 改善 |
|------|--------|--------|------|
| **首次 infer 時間** | 變數 (可能失敗) | 穩定 | ✅ 提升 |
| **顯存使用** | 可能 OOM | 可預測 | ✅ 穩定 |
| **profiling 時間** | 不確定 | 固定 | ✅ 可預測 |
| **GPU 支援** | SM90 為主 | 全支援 | ✅ 更多設備 |

### 🧪 測試要點

1. **低顯存環境測試**：模擬 8GB-12GB 顯存環境
2. **不同 GPU 架構測試**：SM80, SM86, SM89, SM90
3. **壓力測試**：連續多次 profiling 確保穩定性
