# [Bugfix] Avoid merging empty-only partitions into splitting-op subgraphs

- **Issue**: #36595
- **Author**: @ZJY0516
- **Created**: 2026-03-08T08:40:15Z
- **Labels**: `bugfix`, `partition`, `splitting-op`

---

## 🔍 深入分析

### 📋 問題背景

vLLM 的 **分片操作 (splitting-op)** 在處理空 partition 時存在邏輯問題：
- **錯誤行為**：空 partition 被合併到 splitting-op subgraphs 中
- **影響**：可能導致計算錯誤或無效的記憶體分配
- **場景**：動態 batch 或 variable length 輸入時更常見

### 🎯 問題分析

#### 當前問題流程
```python
# 問題：空 partition 被錯誤合併
partitions = [partition1, partition2, partition_empty, partition3]

# 錯誤：空 partition 被包含在 subgraph 中
subgraph = merge_all_partitions(partitions)
# 結果：包含空 partition 的 subgraph
# 影響：無效計算，可能導致錯誤或效能下降
```

#### 技術根源

| 問題點 | 說明 |
|--------|------|
| **partition 檢測** | 未正確識別空 partition |
| **合併邏輯** | 未過濾空 partition 就合併 |
| **subgraph 建立** | 包含無效節點 |
| **計算執行** | 對空數據進行計算 |

### 🛠️ 修復機制

#### 解決方案
```python
# 修復：過濾空 partition
partitions = filter_non_empty_partitions(partitions)

# 建立 subgraph 時跳過空 partition
subgraph = build_splitting_subgraph(
    partitions=partitions,
    skip_empty=True
)
```

#### 關鍵修復點

```python
# 1. 空 partition 檢測
def is_empty_partition(partition):
    return partition.size == 0

# 2. 過濾空 partition
def filter_non_empty_partitions(partitions):
    return [p for p in partitions if not is_empty_partition(p)]

# 3. subgraph 建立時跳過空 partition
def build_splitting_subgraph(partitions, skip_empty=True):
    if skip_empty:
        partitions = filter_non_empty_partitions(partitions)
    return build_graph(partitions)
```

### 📊 影響評估

| 影響層面 | 嚴重度 | 說明 |
|----------|--------|------|
| **計算正確性** | 🔴 高 | 可能導致錯誤輸出 |
| **性能** | 🟡 中 | 無效計算降低效能 |
| **記憶體** | 🟡 中 | 可能浪費記憶體 |

### 🧪 測試要點

1. **空 partition 測試**：驗證空 partition 不被合併
2. **混合 partition 測試**：空 + 非空 partition 混合場景
3. **性能測試**：確保修復後無效能損失
